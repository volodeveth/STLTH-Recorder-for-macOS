# STLTH Recorder for macOS — Design Spec

**Дата:** 2026-08-06
**Статус:** затверджено користувачем (секції 1–5 погоджені в діалозі)

---

## 0. Контекст і мета

Нативний macOS-застосунок (menu bar agent) для запису зустрічей зі співрозмовником
**без бота в дзвінку**. Захоплення звуку локально: голос співрозмовника — із системного
виводу (Core Audio process tap), ваш голос — з мікрофона. Результат сесії —
**два окремі аудіофайли** + `meta.json`.

Мета виконання: не мінімальний прототип, а **продукт максимальної якості**, зібраний
шарами — так, щоб у будь-який момент існував цілісний робочий стан. Вау-ефект
досягається глибиною виконання (edge cases, вимірюваний дрейф, інженерні нотатки,
production-дистрибуція) плюс бонус-шаром поверх скоупу ТЗ.

### Зафіксовані рішення (з діалогу 06.08)

| Питання | Рішення |
|---|---|
| Скоуп | «Максимальний продукт»: повний скоуп ТЗ production-якості + бонус-шар (онбординг, локальна транскрибація whisper.cpp, «Перевірити оновлення») |
| Авто-апдейти Sparkle | **Відхилено** — без Apple Developer підпису непрактично; замінено на пункт меню «Перевірити оновлення» → GitHub Releases |
| Дев-середовище | Оренда Scaleway Mac mini M1 (~€0.11/год, мін. 24 год), розробка з Windows через Remote SSH Remote SSH + VNC |
| Apple Developer Program ($99) | **Ні.** Ad-hoc підпис + інструкція Gatekeeper (right-click → Open) у README |
| Дистрибуція | DMG у GitHub Releases + README/ENGINEERING_NOTES українською |
| Підхід до захоплення | **A: global output tap + один aggregate device** (див. §2) |

### Ключові вимоги ТЗ (стислий витяг)

- macOS 14.4+ (Apple Silicon), цільові версії тестування 15 і 26; UI українською.
- Menu bar agent без вікна в Dock; автозапуск при вході (перемикається).
- Старт/стоп вручну користувачем, у два кліки; стан і тривалість видно завжди;
  повторний клік не створює дубль.
- Без участі в конференції; без віртуальних аудіодрайверів і прав адміністратора
  **в продукті** (на дев-стенді BlackHole дозволений — це тестова інфраструктура).
- Два незалежні файли (mic = ви, system = співрозмовник); розбіжність каналів < 300 мс
  за 60 хв; mute не зсуває таймлайн; файли лишаються локально.
- Згода співрозмовника підтверджується перед стартом; факт і час зберігаються.
- Дозволи видно завжди; при відкликанні — зрозуміла підказка відновлення.
- Приймання: 6 сценаріїв на чистій машині (див. §6 «Приймальна матриця»).

## 1. Архітектурне рішення: захоплення звуку

**Обрано: підхід A — global output tap + один aggregate device.**

- `CATapDescription` на весь системний вивід із виключенням власного процесу
  (mixdown усього, що грає система) — платформонезалежність (Zoom, Meet у Chrome,
  будь-що інше) виконується автоматично.
- Tap + фізичний мікрофон об'єднуються в **один aggregate device** → один IO-колбек,
  один годинник → **синхронність каналів за побудовою**; вимога < 300 мс закривається
  архітектурно, а не постфактум-корекцією.
- Референс робочого коду: AudioCap (Gui Rambo), згаданий у ТЗ.

**Відхилені альтернативи** (аргументація повторюється в ENGINEERING_NOTES):

- **B. Per-process taps** (тапати процеси Zoom/Chrome): чистіший системний канал без
  нотифікацій, але потребує discovery і трекінгу аудіопроцесів (у Chrome звук грає
  окремий utility-процес), ламається при перезапуску процесу, не покриває «живу
  зустріч у кабінеті» з ТЗ. Виграш косметичний, ризики реальні.
- **C. ScreenCaptureKit audio**: працює з macOS 13, але TCC-дозвіл виглядає як «запис
  екрана» (лякає користувача), вмикає системний індикатор запису екрана; ТЗ прямо
  вказує на Core Audio taps як референсний шлях.

Наслідок підходу A: у системний канал потрапляють сторонні звуки (нотифікації).
Документується чесно; рекомендація в README — Focus mode під час зустрічі.

## 2. Компоненти

```
STLTHRecorder/                  (monorepo)
├── App/                        STLTHRecorder.app — menu bar agent (SwiftUI)
│   ├── MenuBarView             старт/стоп, статус+тривалість, останні записи,
│   │                           стан дозволів, налаштування, «Перевірити оновлення»
│   ├── ConsentSheet            підтвердження згоди співрозмовника перед стартом
│   ├── OnboardingWindow        перший запуск: пояснення дозволів      [шар P5]
│   └── AppState                єдиний state machine застосунку
├── RecorderCore/               SPM-пакет, без залежностей від UI — тестований headless
│   ├── AudioEngine             tap + aggregate device + IO proc + запис у файли
│   ├── SessionStore            теки сесій, meta.json, згода, список записів
│   ├── PermissionsService      стани TCC (мікрофон, system audio), deep links у Settings
│   └── DeviceMonitor           зміни аудіопристроїв, назви для meta.json
├── TranscriptionKit/           SPM-пакет: whisper.cpp wrapper                 [шар P5]
├── Tools/drift-check           CLI: тест-сигнал → вимір розсинхрону крос-кореляцією
├── project.yml                 XcodeGen — .xcodeproj генерується, усе скриптовано
├── .github/workflows/ci.yml    білд + юніт-тести (macos arm runner)
└── scripts/                    make dmg, adhoc-sign, release
```

**Формат запису:** CAF / LPCM 48 кГц; `mic.caf` — моно, `system.caf` — стерео.
CAF читається QuickTime без кодеків (критерій №6) і пишеться потоково (crash-safe).

**Тека сесії:** `~/Library/Application Support/STLTHRecorder/Sessions/<UUID>/`
→ `mic.caf`, `system.caf`, `meta.json` (+ `transcript.md` у шарі P5). Нічого не
вивантажується назовні.

**meta.json** (розширює приклад із ТЗ; зайвого не вигадуємо):

```json
{
  "sessionId": "UUID",
  "startedAt": "2026-08-12T14:00:03+03:00",
  "durationMs": 3127000,
  "status": "completed | interrupted",
  "consent": { "confirmed": true, "at": "2026-08-12T14:00:01+03:00" },
  "tracks": [
    { "channel": "mic",    "speaker": "local", "file": "mic.caf",
      "format": "caf/lpcm", "sampleRate": 48000, "channels": 1 },
    { "channel": "system", "speaker": "remote", "file": "system.caf",
      "format": "caf/lpcm", "sampleRate": 48000, "channels": 2 }
  ],
  "devices": { "input": "MacBook Pro Microphone", "output": "AirPods Pro" },
  "deviceChanges": [
    { "at": "2026-08-12T14:20:11+03:00", "input": "AirPods Pro" }
  ],
  "appVersion": "1.0.0", "osVersion": "15.5"
}
```

## 3. Потік даних

```
[Клік «Почати запис»]
→ ConsentSheet («Клієнт дав згоду на запис?») → час згоди фіксується
→ PermissionsService: обидва дозволи є?
     ні → пояснення + кнопка-deep-link у відповідну панель System Settings
→ SessionStore: створює теку сесії, пише meta.json зі status="recording"
→ AudioEngine: створити tap → aggregate device → старт IO
→ [запис: іконка menu bar змінюється, тривалість тікає — «не можна не помітити»]
→ [Клік «Зупинити»] → фіналізація файлів → meta.json: durationMs, devices, tracks,
  consent, status="completed" → сесія в списку «Останні записи»
```

**Інваріант таймлайна:** в обох файлах кількість семплів = тривалість сесії × 48000,
завжди. Тиша пишеться як тиша і ніколи не вирізається. Будь-який розрив потоку
(зміна пристрою, глюк CoreAudio, sleep) компенсується вставкою тиші за таймстемпами.
Це прямо закриває сценарії ТЗ №1 (дрейф < 300 мс) і №4 (10 хв mute).

**State machine:** `idle → preparing → recording → stopping → idle`. Переходи атомарні;
повторний «Старт» у не-idle стані ігнорується (вимога ТЗ про дубль сесії).

## 4. Обробка помилок і граничні випадки

| Кейс | Поведінка |
|---|---|
| Відкликали дозвіл під час запису | Коректна зупинка + фіналізація (записане зберігається); у меню стан «дозвіл відкликано» + кнопка в System Settings |
| Зміна пристрою (AirPods) посеред запису | DeviceMonitor перебудовує aggregate на льоту; розрив → тиша за таймстемпами; подія в `deviceChanges` |
| Sleep / закрита кришка | Пауза з фіксацією події; після прокидання таймлайн доповнюється тишею |
| Мало місця на диску | Перевірка при старті (< ~1 ГБ → попередження); моніторинг під час запису; при критичному рівні — коректна зупинка з повідомленням |
| Падіння застосунку / kill -9 | Файли писались потоково — аудіо ціле; наступний запуск: сесія → status="interrupted", durationMs з фактичної довжини файлів |
| Подвійний клік «Старт» | State machine не дозволяє другу сесію |
| CoreAudio завис (відома болячка) | Watchdog: IO-колбек мовчить > 3 с → перезапуск engine + тиша на місці розриву + запис у лог |

## 5. Тестування

1. **Юніт (CI, без аудіозаліза):** SessionStore, серіалізація meta.json, state machine,
   арифметика таймлайна (вставка тиші). GitHub Actions, macos arm runner, на кожен пуш.
2. **Інтеграційні на маку (BlackHole-стенд):** тестовий WAV → BlackHole →
   «мікрофон»; реальний Zoom/Meet (розробник приєднується «співрозмовником» з Windows) →
   системний канал. **drift-check**: синхронні кліки в обидва тракти → крос-кореляція
   → числовий звіт про розсинхрон у репозиторії.
3. **Приймальна матриця:** README-таблиця «критерій ТЗ №1–6 → кроки відтворення →
   результат/дата». Нічний soak-тест (2+ год). Чиста машина — переустановлення ОС
   на Scaleway (безкоштовна «чиста машина»).

Обмеження стенда (фіксується в ENGINEERING_NOTES): хмарний мак не відтворює фізичні
clock domains (Bluetooth AirPods) — синхронність гарантується архітектурою (§1);
за наявності фізичного Apple Silicon перед здачею проганяється smoke-тест.

## 7. Артефакти

- GitHub-репозиторій: чиста історія комітів, CI.
- DMG у Releases (ad-hoc підпис + інструкція Gatekeeper у README).
- `README.md` (укр.): встановлення, дозволи, приймальна матриця з результатами.
- `ENGINEERING_NOTES.md` (укр.): розвилки і рішення — global tap vs per-process vs
  ScreenCaptureKit; синхронність через aggregate device; інваріант таймлайна;
  обмеження стенда; що взято/відкинуто з AudioCap, Hyprnote, Meetily.

## 8. Ризики

| Ризик | Митигація |
|---|---|
| TCC system-audio дозвіл на headless/VNC маку поводиться дивно | Перевіряється першим у P1 (ворота); AudioCap — доказ, що шлях робочий |
| Аудіопристрої не з'являються без активної GUI-сесії | BlackHole існує завжди; DeskIn/VNC тримає активну сесію |
| LLM-галюцинації на нішевому CoreAudio API | Спайк від AudioCap (реальний код), не з нуля; компіляція на кожен крок |
| Час активації Scaleway/Xcode | P0 стартує сьогодні ввечері; Xcode ставиться пасивно |
| Вигорання «цілодобово» | Довгі записи/soak-тести — вночі без участі людини; агентна розробка вдень |
