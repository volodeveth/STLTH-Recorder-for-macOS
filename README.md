# STLTH Recorder for macOS

Нативний macOS menu bar застосунок, який записує зустріч зі співрозмовником
**без бота в дзвінку**: голос співрозмовника захоплюється із системного виводу, голос
користувача — з мікрофона, у **два окремі синхронні аудіофайли**.

> **Статус:** ядро реалізоване і покрите тестами (68/68 зелених); UI пройшов
> ручний прохід — знайдено і виправлено 13 дефектів (ENGINEERING_NOTES §9).
> Приймальна матриця: **усі 6 критеріїв закриті** реальними прогонами
> (Zoom, Meet, чиста машина) з артефактами в `docs/notes/evidence/`.

## Що це і як працює

| | |
|---|---|
| Платформа | macOS 14.4+ (Apple Silicon) |
| Тип | Menu bar agent (без вікна в Dock), автозапуск при вході — перемикається |
| Захоплення | Core Audio **global process tap** + мікрофон в **одному aggregate device** |
| Формат | CAF / LPCM 16-bit, 48 000 Гц — `mic.caf` (моно), `system.caf` (стерео) |
| Дані | Усе лишається на вашому Mac; жодних мережевих запитів |
| Нагадування | Помічає початок і кінець зустрічі, питає про запис — але ніколи не вмикає його сам |
| Прослуховування | `session.m4a` — зведення обох каналів, ви ліворуч, співрозмовник праворуч |
| Бонус | Локальна транскрибація (whisper.cpp) — сама, після кожного запису, повністю на пристрої |

## Нагадування про зустрічі

ТЗ називає проблему прямо: «хтось просто забуває увімкнути запис, і зустріч
втрачається безповоротно». Тому застосунок стежить за зустрічами сам:

- **почалася зустріч** → «Почалася зустріч у Zoom — увімкнути запис?»
- **зустріч завершилася, а запис триває** → «Зустріч завершено. Запис досі триває.»

Друге важливіше за перше. Забути ввімкнути — втратити зустріч; забути вимкнути —
продовжувати писати кімнату після неї, збираючи аудіо, на яке ніхто згоди не давав.

**Рішення завжди за вами.** Застосунок питає — він ніколи не вмикає і не вимикає
запис сам, як і вимагає ТЗ. Нагадування вимикаються в налаштуваннях.

Зустріч розпізнається за тим, що **якийсь застосунок для дзвінків тримає мікрофон** —
Core Audio повідомляє це по процесах. Не читаються ані вкладки браузера (це вимагало б
дозволу на Apple Events), ані назви процесів. Один механізм покриває Zoom, Google Meet,
Teams, Slack і Webex; диктування та Voice Memos нагадувань не викликають.

## Прослуховування розмови

Після кожної зустрічі поруч із доріжками з’являється **`session.m4a`** — зведений
файл, який можна просто послухати як розмову. У меню: `Останні записи` → сесія →
**Прослухати розмову**.

**Ви ліворуч, співрозмовник праворуч** (85/15, не жорстке панорамування). Вухо саме
розділяє співрозмовників — одразу чути, хто кого перебив, — але обидва голоси
лишаються чутними й на одній колонці.

Зведення **похідне і не є джерелом правди**: `mic.caf` і `system.caf` лишаються
недоторканими, і саме вони йдуть в аналітичний пайплайн. Якщо зведення не вдалося,
сесія однаково повноцінна.

Формат — AAC 96 кбіт/с: година розмови займає ~43 МБ проти ~990 МБ вихідних доріжок.
Файл для прослуховування не вартий того, щоб подвоювати вагу сесії.

Робиться автоматично у фоні; вимикається в налаштуваннях. Жодних зовнішніх
залежностей — усе на AVFoundation, з коробки.

## Локальна транскрибація

Після кожного запису транскрипт робиться сам, у фоні, по одній сесії за раз —
розпізнавання навантажує процесор приблизно стільки ж часу, скільки тривала розмова,
і дві сесії поспіль просто стають у чергу. Вимикається в налаштуваннях
(«Розпізнавати мову після кожного запису»). Руками — `Останні записи` → сесія →
**Транскрибувати**. Працює на whisper.cpp повністю на пристрої; аудіо нікуди не
вивантажується. Якщо моделей немає, автоматично нічого не відбувається і ніхто не
питає — пропозиція завантажити їх живе в меню сесії. Невдале розпізнавання не
робить сесію невдалою: аудіо на місці, транскрипт можна зібрати з меню ще раз.

Розділення за спікерами не вгадується моделлю діаризації: `mic.caf` — це завжди
ви, `system.caf` — завжди співрозмовник.

**Якість на живій українській для поточної моделі (`large-v3`) не міряна.** У 1.3.0
модель замінено з turbo на повну large-v3 з розрахунку на спостереження
Windows-версії того самого продукту (turbo ліпив «Тораз глянемо» там, де повна
модель чує «Та розглянемо»), а не на власний вимір. Попередня модель
(`large-v3-turbo`) давала **8.8 % WER** без урахування формату чисел — методика і
числа в ENGINEERING_NOTES §10; для large-v3 очікується не гірше, але це очікування,
не вимір. Переміряти можна `Tools/wer-live.sh` на реальному Mac.

### Видалення аудіо після транскрибації

**Вимкнено за замовчуванням.** Якщо увімкнути в налаштуваннях («Видаляти аудіо
після розпізнавання»), після успішної транскрибації вихідні `mic.caf` і
`system.caf` видаляються **безповоротно** — оригінали не відновлюються ні з чого.
Лишаються `transcript.md`, `session.m4a` і `meta.json` (у ньому з'являється
`audioRemovedAt`, щоб сесія без аудіо не виглядала пошкодженою). Година розмови —
це ~990 МБ доріжок проти ~43 МБ зведення.

Два запобіжники, обидва без винятків:

- доріжки не чіпаються, якщо транскрипт **порожній** — розпізнавання нічого не
  знайшло, і це привід зберегти аудіо, а не позбутися його;
- доріжки не чіпаються, поки не готовий зведений файл, якщо зведення увімкнене.

Якщо зведення вимкнене, від сесії лишиться тільки текст — налаштування про це
попереджають прямо під тумблером. Правило спільне для автоматичного й ручного
запуску: одна й та сама опція поводиться однаково незалежно від того, як людина
запустила розпізнавання.

### Встановлення транскрибації

Нічого встановлювати руками не треба. У меню: `Останні записи` → сесія →
**«Увімкнути транскрибацію…»**. Застосунок покаже, скільки важать моделі, і
завантажить їх сам — без термінала, без Homebrew і без прав адміністратора.

Знадобиться близько 1 ГБ (1 031 МБ) і кілька хвилин. Завантаження можна перервати:
наступна спроба продовжить з того самого місця, а не почне спочатку.

Якщо на Mac лишилася модель з 1.2.0 (`large-v3-turbo`), розпізнавання працює на ній,
поки нову не завантажено; після успішного завантаження стара видаляється сама.
Обірване завантаження стару модель не чіпає.

`whisper-cli` уже всередині застосунку. Завантажуються **лише моделі** — аудіо
зустрічей нікуди не надсилається ні тоді, ні під час розпізнавання.

На дев-стенді той самий результат дає скрипт, якщо зручніше з термінала:

```bash
scripts/setup-transcription.sh
```

Завантажуються дві моделі, і обидві потрібні:

| Файл | Розмір | Навіщо |
|---|---|---|
| `ggml-large-v3-q5_0.bin` | 1 031 МБ | розпізнавання |
| `ggml-silero-v5.1.2.bin` | 864 КБ | VAD — без нього модель **вигадує текст у місцях тиші**, а зустріч здебільшого з неї й складається |

Свідомо не вшито в застосунок: гігабайт у рекордері, чия основна робота його не
потребує. Запис працює без цього всього — транскрибація лише не з'явиться в меню, і
застосунок прямо скаже, якою командою її додати.

## Архітектура

Ключове архітектурне рішення: tap системного звуку і мікрофон живуть в **одному
aggregate device**, тобто мають **спільний годинник**. Синхронність каналів
досягається побудовою, а не корекцією постфактум — див.
[ENGINEERING_NOTES.md](docs/ENGINEERING_NOTES.md).

## Встановлення

1. Завантажити `STLTHRecorder-<версія>.dmg` зі сторінки [Releases](../../releases).
2. Змонтувати образ і перетягнути **STLTHRecorder** у теку застосунків.
3. **Перший запуск — тільки через правий клік:** ПКМ на застосунку → **Open** →
   у діалозі ще раз **Open**.

**Куди саме перетягувати.** Якщо ви адміністратор свого Mac — у `/Applications`,
як зазвичай. Якщо ні — у **`~/Applications`** (тека `Applications` у вашій
домашній теці; якщо її немає, просто створіть). Системна `/Applications` належить
усій машині, тож macOS попросить пароль адміністратора — це вимога самої системи,
а не застосунку. З домашньої теки він працює точно так само, і **жодних адмінських
прав не потрібно**, як і вимагає ТЗ.

Третій крок обов'язковий і потребує пояснення. Застосунок підписаний **ad-hoc**,
без Apple Developer Program, тож Gatekeeper не має чим підтвердити розробника і
при звичайному подвійному кліку просто відмовить («не вдалося перевірити
розробника»). Правий клік → Open — це штатний спосіб дати згоду вручну; він
потрібен **лише один раз**, далі застосунок запускається як звичайно.

Прав адміністратора, віртуальних аудіодрайверів і системних розширень **не
потрібно** — ані для встановлення, ані для роботи.

Зібрати DMG самостійно:

```bash
scripts/release.sh 1.0.0     # потрібні лише Command Line Tools, Xcode не треба
```

## Перші кроки і дозволи

🚧 *Заповнюється в Tasks 9–10.*

Потрібні два дозволи: **Мікрофон** і **Запис системного аудіо**. Стан обох
завжди видно в меню; при відкликанні застосунок показує підказку і кнопку, що
веде в потрібну панель System Settings.

## Тека сесії

```
~/Library/Application Support/STLTHRecorder/Sessions/<UUID>/
├── mic.caf       # ви, моно — джерело правди
├── system.caf    # співрозмовник, стерео — джерело правди
├── session.m4a   # зведення для прослуховування (ви L, співрозмовник R), похідне
├── meta.json     # метадані сесії, згода, пристрої, тривалість
└── transcript.md # опційно, локальна транскрибація
```

Доріжки підписуються тим, що застосунок справді знає: мікрофон — це **ви**, системний
звук — **співрозмовник**. У `meta.json` це `speaker: local` / `remote`; сесії,
записані версією 1.2.0, несуть старі значення `advisor` / `client` і читаються без змін.

### Що вже виміряно на стенді

Матриця вище — про кінцеві сценарії на чистій машині; вони чекають на Zoom-прогін
і встановлення з DMG. Але частина механізмів уже перевірена числами на
орендованому Mac mini M1 (macOS 26.6), і ці вимірювання варто бачити окремо —
щоб не плутати «ще не перевіряли» з «перевірили, ось число».

| Що перевіряли | Результат | Артефакт |
|---|---|---|
| Мікрофон і tap в **одному** aggregate — передумова синхронності | 185 колбеків, буфери `2ch+2ch` | `docs/notes/evidence/aggregate-layout-probe-after-mic-grant.txt` |
| **Міжканальний дрейф, 60 хвилин, режим `single-aggregate`** | **+6.4 мс/год (95% ДІ ±0.3)** при порозі 300 — запас у ~47 разів; 720 кліків з 720 | `docs/notes/evidence/drift-2channel-60min.md` |
| Дрейф годинника захоплення, 19 хв під навантаженням | −0.7 мс/год, 232 кліки з 232 | `docs/notes/evidence/clock-drift-19min.txt` |
| Інваріант таймлайна на годинному записі | обидва треки 172 801 169 семплів, різниця 0.0 мс | `docs/notes/drift-report.md` |
| Запис у повній тиші (tap не віддає колбеків) | 8.018 с → 384 884 семпли, а не 0 | ENGINEERING_NOTES §3c |
| Виживання після `kill -9` посеред запису | сесія стає `interrupted` з реальною тривалістю 14.680 с; обидва треки читаються **libsndfile**, не лише Apple-стеком | `docs/notes/evidence/crash-recovery-test.txt` |
| 10 хвилин mute (критерій №4) | тиша **записана** (28 320 000 семплів), треки рівні, зсув після паузи 69 мс при порозі 300 | `docs/notes/evidence/mute-10min-test.txt` |
| Зміна пристрою під час запису | два перемикання зафіксовані в `meta.json`, звук присутній після кожної перебудови | `docs/notes/evidence/device-change-test.txt` |
| Поведінка tap у тиші (основа watchdog) | до першого звуку 0 колбеків; після старту 94/с крізь 40 с тиші | `docs/notes/evidence/tap-idle-behaviour.txt` |
| Точність самого вимірювача дрейфу | ±3 мс при порозі 300 | `Tools/selftest_drift.py` |

## Розробка

```bash
make test            # юніт-тести RecorderCore (працюють без Xcode)
make typecheck       # перевірка SwiftUI-шару (теж без Xcode)
make recorder-cli    # headless-стенд запису: ./build/recorder-cli record 30
make drift-selftest  # перевірка drift-інструментів на синтетичному аудіо
scripts/build-app.sh # зібрати STLTHRecorder.app без Xcode
scripts/release.sh   # зібрати DMG для роздачі
```

Вимірювання розсинхрону каналів:

```bash
python3 Tools/gen_clicks.py --out clicks.wav --duration 60 --interval 5
python3 Tools/drift_check.py ~/Library/Application\ Support/STLTHRecorder/Sessions/<UUID>
```
